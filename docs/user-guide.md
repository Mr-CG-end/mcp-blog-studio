# 博客使用与交接手册

## 本地查看

首页：http://127.0.0.1:3000；后台：http://127.0.0.1:3000/admin。
先启动 Docker，按 README 执行数据库启动、迁移、示例数据、构建和启动命令。本地演示账号在 `.local/demo-accounts.md`，此文件不提交 Git，也不进入源码下载。禁止把这些演示账号用于生产。

## 管理员

- 账号：在“账号”中新建用户，填写名称、邮箱、密码、角色。重置密码在账号编辑页操作，不依赖邮件；取消 active 停用账号。不能停用/降级当前登录的管理员。
- 分类：维护名称和 slug；作者使用已有分类。
- 站点设置：名称、介绍、关于正文、可选品牌图片、社交链接。导航设置和页脚设置管理链接。
- 媒体：支持 JPEG/PNG/WebP，最大 5 MB。填写替代文本便于读屏。被当前文章、页面或品牌图引用的媒体必须先解除引用才能删除。
- 操作日志：查看操作者、动作、目标、时间和结果。历史版本恢复的动作是 restore-version。

## 作者写作

1. 登录后台 → 文章 → 创建新条目。填写标题、摘要、正文、分类、封面；默认草稿。
2. 正文工具栏可添加标题、列表、引用、链接、图片块及代码块。slug 用作固定链接，创建后尽量保持稳定。
3. 保存后可从预览入口检查草稿。访客无法看到草稿。
4. 将“发布状态”设为“已发布”并保存；已发布文章后续保存会立即更新公开内容。
5. 状态改为“草稿 / 已下架”并保存即可下架。
6. 文章操作菜单可移到垃圾箱，在垃圾箱恢复后会变成草稿；作者不能永久删除。管理员永久删除不可撤销。
7. 版本页可查看历史。恢复历史版本保留当前归属与 slug，版本号继续增加，状态回到草稿，需要重新发布。
8. 出现 VERSION_CONFLICT 时重新读取最新版本，再合并自己的修改；不要反复提交旧版本。

REST 的 DELETE 是永久删除；回收使用 PATCH deletedAt，与 Payload 后台一致。不要在后续 MCP 中把 DELETE 当成回收实现。

## 交接重点

- v0 普通博客代码已完整实现并通过自动化测试；云资源尚未创建。
- v1 MCP 和 v2 WebMCP 尚未编码。MCP 工具契约与双人模块分工已在 docs 中明确。
- 本地上传文件不进 Git；生产需要 Blob。数据库备份与媒体备份分别处理。
- 普通历史版本可能引用已经删除的旧图片；当前媒体保护只覆盖当前内容。恢复前核对图片是否仍可用。
